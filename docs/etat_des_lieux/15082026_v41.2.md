## 1. Les objectifs du projet

### 1.1 L'objectif final : un organe, pas une application

**Naulthène a vocation à être un cerveau complet en attente d'un corps.** Ce n'est pas une
formule de présentation, c'est le critère qui arbitre chaque décision technique.

MiniGrid n'est **pas la finalité** : c'est un **berceau** — un monde peu coûteux et rapide
où élever, casser et mesurer un cerveau. Ce qui se construit est l'organe : des sens qui
alimentent tous le même espace, un métabolisme qui a faim, une couche réflexe et une couche
délibérative, une mémoire qui abstrait par répétition, un cycle jour/nuit qui consolide ou
oublie.

Le test de cet objectif est vérifiable mécaniquement : **rien dans le cœur ne nomme
« grille », « clé » ni « porte »**. C'est cette absence qui rend envisageable le
remplacement du berceau par une caméra, un micro et un bus moteur — le même `nn.Module`
devrait continuer de tourner.

*Direction long terme affichée* : une intelligence généraliste sur une puce Apple Silicon,
sans datacenter. C'est une direction, pas une promesse.

### 1.2 La thèse défendue : l'unification, pas la légèreté

Les architectures cognitives grossissent d'ordinaire par **addition** — un module vision, un
module mémoire, un planificateur, un routeur qui arbitre. Naulthène grandit par
**compression** : un seul bus latent (64 dims) porte tout, et chaque faculté est une
projection dans ou hors de ce bus.

```
    vue    ─┐                                    ┌─ moteur (C1, réflexe)
    ouïe   ─┤                                    ├─ valeur (C2, néo-cortex)
    toucher─┼──►  BUS LATENT (64 dims)  ────────►┼─ modèle du monde (JEPA)
    odorat ─┤     un vecteur, un espace          ├─ voix
    goût   ─┘                                    └─ port exocortex (C3)
```

Trois conséquences, chacune testable :

| Affirmation | Statut mesuré |
|---|---|
| La substitution sensorielle est gratuite (aucun chemin de repli à écrire) | ✅ **vérifiée** — 78 cellules d'ablation, aucun plantage, aucune branche de code alternative |
| Ajouter un sens est **additif**, jamais structurel | ✅ **fait deux fois** — odorat (v32), Exo-Sens (v30), par ajout de dimensions en queue |
| Une seule règle de plasticité gouverne les 12 couches | ✅ **vérifiée** sur 1300 nuits |

⚠️ **Ce que la thèse ne couvre pas.** La **légèreté n'est pas démontrée** : à 55 232
paramètres, Naulthène est **2,85× plus lourd** qu'un PPO CNN (19 384) et à parité avec un
CNN+LSTM (52 664). Le cœur strictement comparable pèse 30 464 paramètres, le reste (45 %)
achetant ce qu'aucun baseline n'a (audio/vocal, JEPA, intégrateur bio, port C3). Le
benchmark à budget égal **n'a pas été lancé**.

### 1.3 Les principes de conception (les vraies contraintes)

Ce sont eux qui expliquent la majorité des refus d'implémentation du projet.

| Principe | Formulation | Conséquence pratique |
|---|---|---|
| **Rien en dur** | Une constante est une **borne**, jamais une valeur de fonctionnement. Les valeurs sont **dérivées** du vécu | `reference_choc_dopamine` : le même choc de 0,1 vaut **100 %** pour un débutant, **11,4 %** pour l'expert |
| **Pas de seuil dans le chemin cognitif** | Un `if` déguisé en sigmoïde reste un `if` | Le court-circuit C1→C2 refusé (v29), l'appel à C3 sur incertitude refusé (v28), la boucle d'attention Exo refusée (v30) |
| **Ça doit émerger, pas être formulé** | Si un comportement peut naître de la mécanique, il ne se code pas | v40.1 : **9 branches supprimées**, 3 interrupteurs cognitifs rendus continus |
| **Rien n'est expliqué au cerveau** | Aucune table `lave = danger`, `clé = utile` | Les étiquettes restent **opaques** ; la valence est apprise par accumulation de chocs |
| **Instrumenter avant de rendre adaptatif** | Remplacer un chiffre arbitraire par une **formule** arbitraire ne vaut pas mieux | Mesurer d'abord, dériver ensuite, vérifier que l'adaptatif fait **mieux** que le fixe |
| **Ne jamais masquer l'état réel** | L'échec fait partie du carnet | Les README publient les chiffres défavorables, y compris ceux qui contredisent le projet |

### 1.4 L'objectif immédiat (roadmap)

1. **Rendre la thèse falsifiable** — remplir les trois tables de benchmark, dont la comparaison à budget égal contre PPO, qui seule distingue « élégant » de « moins performant ».
2. **Débloquer le cursus** — cinq bloquants mesurés, **aucun n'est cognitif**.
3. **Le liage multimodal** — les dix paires de sens, sous contrainte que le système continue de fonctionner avec **un seul** sens.

## 2. L'état du système cerveau

### 2.1 Ce que le cerveau EST, physiquement

Un unique `nn.Module` (`AGI_Naulthene`), **douze couches**, **55 232 paramètres**, 0,21 Mo
en fp32.

| Couche | Dimensions | Rôle |
|---|---|---|
| `porte_visuelle` | 147 → 64 | 9 408 — entrée vue |
| `porte_auditive` | 130 → 64 | 8 320 — entrée ouïe (MFCC) |
| `hippocampe` | 128 → 64 | 8 192 — mémoire de travail |
| `fusion_memoire` | 128 → 64 | 8 192 — lecture épisodique |
| `integrateur_bio` | 100 → 64 | 6 400 — 5 sens + homéostasie |
| `generateur_attente` | 72 → 64 | 4 608 — **JEPA visuel** |
| `generateur_attente_audio` | 72 → 64 | 4 608 — JEPA audio |
| `analyseur` | 64 → 64 | 4 096 — tronc |
| `tete_motrice` | 64 → 8 | 512 — **C1** |
| `tete_vocale` | 64 → 8 | 512 — la bouche |
| `tete_requete` | 64 → 5 | 320 — routage C3 |
| `cortex_prefrontal` | 64 → 1 | 64 — **C2** |

**Empreinte mémoire réelle** : 0,211 Mo de poids, mais **1,683 Mo en entraînement** — les
buffers de plasticité (myéline, traces, normes de naissance) coûtent **5× les poids
eux-mêmes**. C'est le prix du cycle jour/nuit, et une cible d'optimisation identifiée.
Tourne sur `mps` (Apple Silicon) aujourd'hui.

### 2.2 Comment il fonctionne — les six mécaniques

**a) Le tronc et les deux systèmes de décision.**
`porte_visuelle` → `hippocampe` → `analyseur` forment le tronc commun. Puis :

- **C1 (réflexe)** — compresse les 5 sens en `pensee_bio`, émet les logits moteurs à coût quasi nul.
- **C2 (néo-cortex)** — rollout mental multi-échelle à travers le JEPA, sur des **sauts exponentiels** t+1, t+3, t+7.

```python
logits_final = (logits_instinct × gain_c1) + (valeurs_simulees × force_planification)
```

Deux invariants gouvernent cette frontière :
- **C2 est sollicité à CHAQUE tick** — aucun seuil de confiance, aucun court-circuit. Refusé quatre fois.
- **C2 ne reçoit jamais que l'état déjà compressé par C1** — jamais les pixels, jamais l'environnement.
- Le rollout ne branche sur les 7 actions **qu'au premier pas** ; les suivants suivent l'argmax. C'est ce qui maintient la complexité **linéaire** au lieu de $7^{horizon}$.

**b) Les six sens, hiérarchisés par gourmandise énergétique.**

| Sens | Dims | Gourmandise | Chemin |
|---|---|---|---|
| 👁 Vue | 147 | extrême | `porte_visuelle` → **bus latent** (cible JEPA) |
| 👂 Ouïe | 130 MFCC | élevée | `porte_auditive` → **bus latent** (JEPA audio) |
| ✋ Toucher | 4 | moyenne | queue du `vecteur_bio` → `integrateur_bio` |
| 👃 Odorat | 2 | faible | idem — distance **topologique** (BFS), pas euclidienne |
| 👅 Goût | 2 | faible | idem |
| 🌐 Exo-Sens | 8 | — | perception **continue** du monde numérique via le Port C3 |

Les sens faibles n'entrent **jamais** dans le bus latent : ils passent par `integrateur_bio`,
donc restent **hors de la cible JEPA**. C'est ce qui garantit qu'ajouter trois canaux bruités
ne perturbe pas le modèle du monde d'un cerveau déjà entraîné.

**c) La plasticité jour/nuit** — le cœur de l'unification.
Chaque couche porte un `base_weight` figé et un `annexe_weight` appris dans la journée.
Chaque nuit :

```python
myeline_M = max(myeline_M, |annexe_weight|)               # rafraîchie AVANT usage (v37.0-fix)
base     += annexe                                         # consolidation
echelle   = max(historique, quantile(myeline_M, 0.75))     # RELATIVE, pas absolue (v37.0-fix)
base     *= 1 − λ(1 − clamp(myeline_M / echelle, 0, 1))    # érosion géométrique
base     *= clamp(norme_naissance × 0.10 / ‖base‖, min=1.0) # plancher vital, JAMAIS un plafond
```

Les trois marqueurs `v37.0-fix` sont trois bugs qui rendaient l'apprentissage des têtes de
décision **mathématiquement impossible**, non détectés pendant des centaines de jours simulés.

**d) Le rêve adaptatif** — le pourcentage de souvenirs rejoués **émerge** de la plasticité ×
la richesse de la journée, jamais d'une taille de batch fixe. Mesuré : 15–18 % de la journée
rejouée, ~70 rejeux par nuit.

**e) La mémoire à flux enrichi (v36)** — un doublon n'est jamais jeté : il **confirme**
(`confirmations`), et affine une `valence` apprise. L'oubli retire le repère **le moins
confirmé**, pas le plus ancien : une régularité du monde survit, un accident se dégrade.
Mesuré : 108 confirmations par repère, 73 % de taux de rappel.

**f) Le métabolisme homéostatique** — trois (bientôt quatre) jauges vitales, un réservoir
dopaminergique $D_t \in [0{,}001\,;\,10]$, et un déficit
$D(t) = \sum (1-\text{jauge})^2$ dont `r_bio` est la **dérivée**.

### 2.4 Les contraintes et les blocages — ce qui ne va pas

**a) Le cursus ne progresse plus.**

| Métrique | Valeur |
|---|---|
| Niveau atteint | **1 sur 15** — 10 graines × 2000 jours, **0 promotion** |
| Maîtrise maximale (seuil : 60 %) | **40 %**, sur 7 602 victoires cumulées |
| Mécaniques cognitives ayant amélioré quelque chose | **0 sur 9 testées** |
| Leviers qui ont marché | **2 — tous deux des propriétés du MONDE** |

Une graine antérieure (g22) a atteint le niveau 4 et s'y est tenue 1223 jours. La campagne de
10 graines fraîches a tranché : c'était une **loterie natale**, pas une propriété du
correctif. La divergence est visible dès la **nuit 1**, avec un écart de `danger` de **38×**
au jour 50.

**b) C2 est causalement déconnecté du comportement.** C'est le résultat le plus dérangeant.

| Mesure | Résultat |
|---|---|
| `c2_coupe` (`force_planification = 0`) | **+0,0 point sur les 6 niveaux** |
| `c2_horizon_court` (horizon 1) | **+0,0 point sur les 6 niveaux** |
| Accord C1/C2 : jour 500 → 1000 → 1500 → **2000** | 37 % → 21 % → 4 % → **0,5 %** |

Douze mesures, deux cerveaux indépendants, 300 épisodes par cellule, **douze zéros exacts**.
Le système délibératif n'est ni nuisible ni utile : il est **débranchable sans effet**. Le
réveil de C2 obtenu en v41 (37 % d'accord) était un **transitoire de 500 jours**.

**c) Quatre sens sur six sont inertes, et les trois mémoires sont plutôt nuisibles.**

| Lésion | Effet |
|---|---|
| Ouïe, goût, odorat, Exo-Sens coupés | **0,0** — aucun effet mesurable |
| **Toucher** coupé | −4,4 à **−6,7** — porte réellement quelque chose |
| **Vecteur bio** neutralisé | −4,4 → **−8,0** (le coût grandit avec la difficulté) |
| Vue neutralisée | **instable** — aide sur 3 niveaux, nuit sur 3 |
| Mémoire de travail **figée** | **+2,0 à +4,7** — *améliore* le score sur 4 niveaux sur 6 |
| Contexte épisodique **neutralisé** | améliore sur 4 niveaux sur 6 |
| Mémoire spatiale vidée | **−7,4** sur `Primaire 3 (Ramasser)` — la seule exception nette |

**d) Le banc d'essai lui-même était biaisé.** Une revue de code des 13-14 août a montré que
jusqu'à **une carte sur deux** était gagnable **sans la clé**. Corrigé — mais la tâche est
alors devenue **50× plus dure** (réussite d'une politique aléatoire sur `8x8` :
15,3 % → 0,3 %). **Les résultats antérieurs ne sont pas comparables aux suivants.**

**e) Les cinq bloquants mesurés — aucun n'est cognitif.**
Patience plafonnée à 120 ticks contre 256 pour MiniGrid lui-même (réussite atteignable
4,7 % contre **21,0 %**), saut de difficulté ×10 au niveau 2, espérance d'épisode à
**−1,06**, 4 actions sur 7 inertes sur une pièce vide, et une ère de cursus qui double les
épisodes perdants.

**f) La saturation** — le « fil n°2 » de l'INDEX, rencontré **sept fois**. Une variable
saturée cesse de porter de l'information, dans un sens **comme dans l'autre** :
`envie` = 1,0000 sur 10 graines depuis le jour 263, `danger` = 676 sur 9 graines à l'unité
près, accord C1/C2 = 0 % sur 7 graines.

### 2.6 Le chantier en cours — v41.2, le métabolisme à deux étages

**Statut au 15/08/2026** : 3 commits + 1 diff non commité sur `feat/v41-ligne-flottaison`,
**non encore entré au CHANGELOG**.

**Le défaut mesuré** : l'agent vit **400 ticks sur 400 en zone critique métabolique**, tous
les jours, sur les 10 graines. L'échelle temporelle est fausse d'un facteur **~35** —
satiété pleine → vide en 86 ticks, quand une journée en compte 400 (et 3600 dans la référence
nycthémérale du code lui-même).

Une fois les jauges au plancher, elles ne peuvent plus descendre : `r_bio` devient un bruit
constant à −0,0011. **Le vécu perd sa variance, donc son information** — ce qui explique
directement `danger` saturé, `envie` saturée, et surtout : *un agent en famine permanente
n'a rien à planifier, il n'a qu'une urgence*. C'est une **cause amont** possible de la
déconnexion de C2.

Ce qui est livré ou en cours :

| Élément | Contenu |
|---|---|
| **La vigueur** (`énergie^κ`) | un **modulateur global unique** au lieu de dix branchements. À κ=2, une énergie à 0,5 laisse C1 à 50 % mais C2 à **25 %** : la délibération s'éteint **plus vite que le réflexe** — hiérarchie de survie obtenue gratuitement, **sans aucun `if`** |
| **Profil nutritionnel à 3 axes** | une ressource n'est plus « un type qui remplit sa jauge » : `satiete` / `hydrique` / `energie` + son **coût de digestion**, exprimé en fraction de son propre apport. Mesuré : eau seule → mort de faim au tick 367 ; nourriture seule → mort de soif au tick 587 |
| **Densité de ressources dérivée** | 2 → 5 par carte, dérivée du besoin réel |
| **Découplage hydrique** (diff non commité) | chaque axe dérive sa portion de **sa propre** perte journalière. Une portion partagée donnait une eau à 0,889 sur une jauge plafonnée à 1,0 : boire tôt **gaspillait** (2,0 unités perdues/jour), boire tard trouvait la conversion déjà bridée |

**Le verdict du run de 300 jours** : la tendance énergétique est **descendante** (0,172 →
0,079), pas ascendante ; seuls 10 % des jours ont une énergie saine. L'agent trouve 1,92
nourriture/jour là où le métabolisme en demande 2,5 — et ce taux **n'augmente pas** sur 71
jours. **Ce n'est pas un débutant qui rattrape, c'est un déficit structurel.**

*Acquis malgré tout* : l'agent **ne meurt plus** et **gagne** (26 victoires en 65 jours),
l'énergie **alterne** (0,86 ↔ 0,03) au lieu de s'effondrer, et okay/danger a **retrouvé de la
variance** contre 676 saturé en v41.

> ⚠️ **Un arbitrage est ouvert et attend l'utilisateur.** Deux corrections sont possibles,
> une seule est honnête : baisser `REPAS_PAR_JOURNEE` calerait le barème sur ce que l'agent
> trouve déjà — donc supprimerait la pression et rendrait la mécanique « verte » **sans rien
> démontrer**. Agir sur la **trouvabilité** (le monde) est cohérent avec le seul levier qui
> ait jamais marché sur ce projet.

## 3. Le parcours — progression, grilles, nourriture, jours, ticks

### 3.1 Les quatre parcours

Naulthène n'a **pas un seul cursus** : quatre écosystèmes distincts, chacun avec **son propre
fichier `.brain`**. Tous lancent le **même** cerveau — seule la boucle qui pilote les journées
change.

| Parcours | Script | Durée visée | **Ticks/jour** | Ce qu'il ajoute |
|---|---|---|---|---|
| **Cursus par Ères** | `cursus_developpemental.py` | 1000 jours | **400** | MiniGrid + vocal, en alternance puis fusionnés |
| **Cerveau Bébé** | `cursus_bebe.py` | 1440 j (~4 ans) | **3600** | Récompense externe **masquée** les 240 premiers jours |
| **Cursus de la Parole** | `cursus_parole.py` | 900 jours | **800** | Voix réelle de l'utilisateur, synesthésie |
| **La Cuve** | `daemon_cerveau.py` + clients | illimité, manuel | pas de « jour » fixe | Contrôle tick par tick |

### 3.2 Jours et ticks — l'unité de temps

- **Un tick = une décision de l'agent** (une action jouée, ou une itération de babillage).
- **Une journée = 400 ticks** dans le Cursus par Ères : ticks 0–199 le matin (MiniGrid), 200–399 l'après-midi (vocal).
- **400 n'est pas arbitraire** : c'est le seuil minimal en dessous duquel `apprendre_journee` ne se déclenche pas.
- **Une nuit** = `executer_nuit` : apprentissage (Acteur-Critique + JEPA) → rêve → cycle de sommeil (consolidation + érosion) → sauvegarde du `.brain` → ~90 métriques W&B.
- **Sauvegarde après chaque nuit** : un `Ctrl+C` ne perd au pire que la journée en cours.
- `--jours N` ajoute **N jours SUPPLÉMENTAIRES** à l'état repris — jamais une valeur absolue.

⚠️ **Tension d'échelle connue** : la journée de référence *nycthémérale* du code est **3600**
ticks (`TICKS_PAR_JOUR_BEBE`), mais le cursus principal tourne à **400**. C'est le cœur du
diagnostic v41.2 (§2.6). L'invariant à préserver lors d'un changement d'échelle est le **vécu
biologique** (mêmes repas/journée, même profil de jauges en % de journée), **pas** le nombre
de ticks.

tout réapprendre.

| 5 | `Fetch-5x5-N2` | **Primaire 3** | manipuler un objet |
| 6 | `GoToDoor-6x6` | **Collège 1** | la porte devient une cible |
| 7 | `DoorKey-5x5` | **Collège 2** | clé + porte, carte minimale |
| 8 | `DoorKey-6x6` | **Collège 3** | même tâche, plus grand |

### 3.4 Comment on passe au niveau suivant

Deux voies coexistent en **OU** :

| Voie | Critère | Caractère |
|---|---|---|
| **Série** (historique) | **2 victoires consécutives** | rapide, mais une défaite remet à zéro |
| **Maîtrise** (v35.0) | **60 %** de réussite sur les **20** derniers épisodes | lent à établir, robuste |

Quatre invariants encadrent la promotion :

1. Le taux n'est calculé qu'à partir de **10 épisodes** observés — « pas encore mesurable » n'est pas « mesuré à zéro ».
2. La fenêtre est **vidée à chaque promotion** — sinon un taux hérité d'un niveau facile promouvrait en chaîne.
3. La réussite se juge sur `recompense_env > 0`, **jamais sur `termine` seul** : `termine` vaut aussi True quand l'agent **meurt dans la lave**.
4. `niveau_actuel` est un **index** : un ancien `.brain` est **remappé par `env_id`** (`🔀 Niveau remappé : index 4 → 14`), aucune progression perdue.

**La promotion observée est un DÉBLOCAGE, pas une montée.** Sur la seule graine qui ait
progressé : jour 770 → niveau 2, jour 775 → niveau 3, jour 778 → niveau 4, puis **plus rien
pendant 1223 jours**. Trois paliers en 8 jours après 769 jours de plateau — la compétence
était là bien avant, il manquait le seuil.

### 3.5 Les 7 paliers DoorKey (sous-cursus)

À l'intérieur du niveau Collège, une décomposition **spécifique à `DoorKey`** contre le
problème du *sparse reward* :

| Palier | Nom | Validation |
|---|---|---|
| 1 | **Regarder** | orienté vers la clé/porte dans le champ de vision |
| 2 | **S'approcher** | distance à la clé < 2 cases |
| 3 | **Toucher / Prendre** | clé dans l'inventaire |
| 4 | **Transporter** | déplacement > 3 cases en gardant la clé |
| 5 | **Viser la Porte** | positionné adjacent à la porte verrouillée |
| 6 | **Déverrouiller** | `Toggle` exécuté face à la porte |
| 7 | **Franchir & Sortir** | traversée + contact avec l'objectif |

⚠️ Ce détecteur est **le seul composant du cœur spécifique à un environnement** — il ne doit
pas être réutilisé tel quel ailleurs. Les autres détecteurs (`DetecteurFranchissementPortes`,
`DetecteurProgresPersonnel`) sont **agnostiques de la carte**, par construction.

### 3.6 La nourriture et le métabolisme

**MiniGrid n'a pas d'objets Nourriture/Eau natifs.** Le projet les fabrique sans jamais coder
de carte en dur : `DetecteurRessourcesBiologiques` réutilise l'objet `Ball` avec une couleur
dédiée — **rouge = Nourriture, bleu = Eau** — placées sur des cases vides aléatoires à chaque
`reinitialiser_episode`, et retirées de la grille dès consommation.

**Les jauges vitales** (Théorie de la Réduction du Drive, Hull 1943) :

| Jauge | Rôle | Dégradation par tick |
|---|---|---|
| **Satiété** | nourriture / énergie motrice | $-0{,}008 \times (1 + \text{effort})$ |
| **Hydratation** | fluide informationnel | $-0{,}005$ (constant) |
| **Stimulation** | découverte / complexité | $-0{,}012$ + bonus de nouveauté |

$$D(t) = (1-\text{satiété})^2 + (1-\text{hydratation})^2 + (1-\text{stimulation})^2
\qquad r_{\text{bio}} = D(t-1) - D(t)$$

`r_bio` est **positif quand l'agent comble un manque**, négatif s'il continue de se dégrader.
Il est injecté dans le réservoir dopaminergique existant — **une seule notion de motivation**,
jamais deux qui se chevauchent.

**Le métabolisme 20/80** : l'effort qui creuse la satiété est
$0{,}80 \times \text{coût\_corps}(\text{action}) + 0{,}20 \times \text{coût\_cerveau}(\text{force\_planification})$.
Tourner coûte 0,2 · avancer 0,5 · manipuler **0,8** (le plus cher) · `toggle` 0,6 · `done` 0,1.
**Penser coûte aussi** : le rollout mental est facturé.

**Le forage 80/20** : la Nourriture (seule — l'Eau ne respawn pas) réapparaît après
consommation, à **80 %** près d'un « Nid » (la première case vide trouvée à l'initialisation,
jamais une coordonnée codée en dur) et à **20 %** dispersée aléatoirement.

**Les quêtes de survie** : sous `SEUIL_CRITIQUE_BIO = 0,35`, une quête intrinsèque est
générée par ordre de priorité `SURVIVAL_FOOD` > `SURVIVAL_WATER` > `EXPLORATION_STIM` —
mourir de faim est plus urgent que s'ennuyer.

**Depuis v41.2** (§2.6), une ressource porte un **profil à trois axes** + son coût de
digestion :

| | satiété | hydrique | énergie | digestion |
|---|---|---|---|---|
| **WATER** | 0,0 | **1,0** | 0,0 | 0,0 |
| **FOOD** | **1,0** | 0,03 | **1,0** | 0,15 |

L'eau hydrate à 100 %, zéro calorie, digestion gratuite. La nourriture remplit le stock,
hydrate à peine, et **se paie à l'ingestion**. Les deux axes sont réellement contraignants :
eau seule → mort de faim au tick 367 ; nourriture seule → mort de soif au tick 587.

⚠️ **Rien n'est expliqué au cerveau** : aucune table `pomme = bon`. L'agent ne perçoit que les
conséquences sur ses jauges ; la valence de chaque type reste **apprise** par
`empreinte_types`. Ce tableau décrit **le monde**, pas une connaissance donnée.

### 3.7 Le déroulé d'un run

**Les 3 Ères du Cursus par Ères** — transition automatique sur `etat.jour`, rien à activer :

| Ère | Jours | Matin | Après-midi |
|---|---|---|---|
| **Alternance** | 1–399 | MiniGrid seul (silence total) | Vocal seul, agent immobile |
| **Synesthésie** | 400–599 | MiniGrid **+ audio simultané** | Vocal seul |
| **Intégration** | ≥ 600 | MiniGrid **+ verbalisation de l'action jouée** | journée continue |

**Deux progressions indépendantes en parallèle sur le même cerveau** : le niveau MiniGrid
(15 paliers) et le palier vocal (1 à 19). *Le palier vocal est à **19** — le seul cursus qui
progresse encore.*

**La patience adaptative** — un épisode ne s'arrête pas sur un plafond fixe de ticks, mais sur
un seuil recalculé chaque jour à partir du taux de succès et de la vitesse des succès passés.
Dépassé, l'agent déclenche une **troncature volontaire (abandon lucide)**, avec une friction
dopaminergique **douce** plutôt qu'un choc traumatique.

⚠️ **C'est le bloquant le mieux mesuré du projet** : la patience plafonne à 120 ticks contre
**256** pour MiniGrid lui-même — réussite atteignable **4,7 %** contre **21,0 %**.

**Le guidage dégressif et le filet (v35.1)** — un seul curseur : *plus il comprend, moins on
l'aide ; quand il bloque, on l'aide un peu*. L'aide décroît avec la maîtrise **mesurée** (1,00
sous 60 % → 0,00 au-dessus de 90 %), et un agent qui stagne plus de 30 jours reçoit un surplus
progressif jusqu'à ×3, replié dès la première victoire. **La redescente de palier a été
écartée** : on n'aide pas un agent en le faisant reculer.

**Commande type** :

```bash
WANDB_MODE=offline PYTHONPATH=src python -m naulthene.salles_de_classe.cursus_developpemental \
    --jours 1000 --brain "brains/$(date +%d%m%Y%H%M)_V41_1000_RMD.brain"
```

Un `.brain` par run — deux runs partageant le même fichier s'écrasent mutuellement.

### Le fil rouge de tout le projet

> **Ce qui rend possible fait progresser · ce qui facilite ne change rien · ce qui fait à la
> place fait régresser.**

Les deux seuls leviers ayant jamais produit un effet mesurable sont des propriétés du
**monde**, pas du cerveau. C'est l'observation la plus robuste du projet, et elle oriente le
chantier v41.2 en cours : ne pas caler le barème sur ce que l'agent atteint déjà, mais rendre
le monde **habitable**.
